# 🧠 Мозг ИИ: тактические решения монстра (AI Brain)

Документ описывает, **как** боевой ИИ принимает решения и **что** дизайнер
может крутить, чтобы поменять его поведение. Связан с
[Сущности и Хаос](./04_combat_entities.md): «Ghost Agent» — это и есть
актёр, который пользуется этим мозгом.

> Реализация и контракты — [`docs/ru/backend/features/combat/runtime/ai.md`](../../../ru/backend/features/combat/runtime/ai.md).

---

## 1. Что изменилось

**Было:** монстр получал каждого противника отдельно, выбирал случайный
финт из руки с шансом 50%, не учитывал защиту цели, HP, наличие
стамины и токенов.

**Стало:** монстр видит **весь свой ход целиком** — всех своих
противников, всю свою руку, все свои ресурсы — и распределяет финты
между намерениями так, чтобы каждый финт пошёл в то место, где он
реально работает.

Симметрия с игроком сохранена: монстр получает ту же случайную «руку из
трёх финтов» каждый раунд через тот же `FeintService`. ИИ не видит
скрытые данные игрока и не лезет в полный арсенал в обход системы.

---

## 2. Тактические оси решения

Каждое потенциальное действие монстра получает «скор» — сумму
взвешенных сигналов. Дизайнер крутит веса в JSON-файле политики,
никакого кода писать не нужно.

### Оси цели

| Ось | Смысл |
|---|---|
| `target_low_hp` / `target_high_hp` | Приоритизация подранков или, наоборот, размен с танком. |
| `finishable` | Цель в зоне добивания (≤25% HP) — даёт дополнительный буст к скору. |
| `control` (на цели) | Цель уже под контролем (стан/root/нокдаун) — выгодно её добивать. |
| `bleed` (на цели) | На цели уже идёт кровотечение — продолжать давление. |

### Оси действия (теги)

| Тег | Когда возникает |
|---|---|
| `anti_block` | Финт ломает блок (`block_mult`, токен `block`, `applicability_tags`). Умножается на текущий блок цели. |
| `anti_parry` | Финт ломает парирование (`parry_mult`, токен `parry`). Умножается на парирование цели. |
| `anti_evasion` | Финт ловит уклониста (`dodge_mult`/`evasion_mult`, токен `dodge`). Умножается на evasion цели. |
| `armor_bypass` | Финт игнорирует/пробивает броню. Умножается на «плотность» брони (capped). |
| `control` | Финт накладывает контроль (стан/root/blind/concussion). Бот ценит «прибить инициативу». |
| `bleed` | Финт накладывает кровотечение (длительный урон). |
| `debuff` | Финт навешивает дебафф на цель (снижение силы или защит). |
| `multi_target` | Финт бьёт по нескольким — ценится тем сильнее, чем больше живых врагов. |
| `preparation` | Финт «затравочный», открывает следующий ход. |
| `counter` | Финт строится на контратаке — масштабируется на counter-attack цели. |
| `damage_tag` | Тег «обычного» урона. Базовая ось любой атаки. |
| `heal` | Самолечение (например `second_breath`, `perfect_riposte`). Ценится тем сильнее, чем ниже HP бота. |
| `self_buff` | Подготовка к следующему ходу (preparation_effect на source). |
| `defense` | Защитная техника (active_defense, brace_guard, и т. д.). Ценится при низком HP. |
| `group_basic` / `group_tactical` / `group_weapon` | Школа финта по `purchase_group`. Позволяет настроить cost-vs-school предпочтение. |
| `blood_resource` / `counter_resource` / `gift_resource` | Бот **уже имеет** соответствующие токены — есть «запас» под нужный стиль. |

### Оси ресурсов

| Ось | Смысл |
|---|---|
| `token_cost` | Цена в тактических токенах. Обычно отрицательная — трата штрафуется. |
| `stamina_cost` | Цена в стамине. Обычно отрицательная. |
| `self_low_hp_resource_save` | Бот ранен (HP ≤ 30%) → дополнительный штраф за трату ресурса. «Если умираю — не разбрасываюсь». |
| `self_low_stamina_save` | Стамина ≤ 30% → дополнительный штраф. «Дышу через раз — не размахиваюсь». |

### Шум

| Ось | Смысл |
|---|---|
| `randomness` | σ контролируемого шума в скоринге. По умолчанию 0.05 — слабый. Поднимать, если ИИ слишком предсказуем; опускать, если ИИ слишком разваливается. |

## 3. Распределение ресурсов между намерениями

Бой одновременный: монстр выставляет намерение **на каждого** своего
противника. Финт в руке использовать можно **только один раз за ход**,
стамина — общая на все намерения.

ИИ работает по правилу «жадно лучшему»:

1. Для каждой цели прикинуть, насколько финт улучшает скор по сравнению
   с чистой атакой.
2. Отсортировать цели по этому приросту.
3. Финт уходит к той цели, где он даёт больше всего пользы, при условии,
   что стамины хватит.
4. Оставшиеся цели получают чистую атаку.

**Пример:**

Монстр держит в руке `weapon_bind` (anti_parry). Противники:

- T1 — танкующий мечник, парирование 0.5;
- T2 — лучник, парирование 0.05.

Финт пойдёт против T1, потому что там он реально срывает большую долю
парирования. T2 получит обычный удар. Это правильное решение даже для
игрока: тратить anti-parry на цель без parry — потерянный финт.

## 4. Что НЕ происходит во время реального боя

Это критично понять и дизайнеру, и стороннему наблюдателю.

- ИИ **не учится** в живых боях с игроками.
- Веса политики **не меняются** в рантайме.
- Между двумя одинаковыми боями с одинаковым seed-ом монстр поведёт себя
  **одинаково**.

Обучение — **отдельный оффлайн-скрипт**, на синтетических сценариях.
Дизайнер крутит сценарии и веса, тренирует, проверяет, подкладывает
артефакт в воркер. Это явный, повторяемый процесс — никакого
«поломанного боя из-за неудачного апдейта политики».

Online-learning от телеметрии живых боёв — возможная **будущая** ось,
но даже она пойдёт через офлайн-пайплайн: «логи → сценарии → обучение
→ деплой». Сам бой остаётся read-only.

## 5. Балансировочные ручки

Что можно сделать **без правок кода**:

| Я хочу | Что крутить |
|---|---|
| Монстры слишком сильно тратят ресурсы → пустеют к концу боя | Опустить `token_cost` / `stamina_cost` дальше в минус. |
| Монстры слишком пассивны, не используют финты | Поднять `damage_tag` и `anti_*` веса. |
| Монстры слишком хорошо добивают подранков → бои безнадёжные | Опустить `finishable`. |
| Монстры одинаково ведут себя в каждом бою → скучно | Поднять `randomness` (0.05 → 0.1–0.15). |
| Босс должен играть тоньше | Подготовить отдельный `boss_policy.json`, подложить через `COMBAT_AI_POLICY_PATH`. |
| Миньон должен играть тупее | Опустить веса в `minion_policy.json` или прописать высокий `randomness`. (Per-archetype ещё не подключено — см. deferred ниже.) |

Что **требует** правок кода (но швы готовы):

- Способности (instant/heal/ability) как опции выбора, а не только финты —
  поле `action_type="instant"` зарезервировано, теги/веса уже встают рядом.
- Per-archetype политики через `MonsterAIProfileDTO.behavior`/`tags`.
- Более «слепой» observation для миньонов (видят только грубое HP,
  округлённые защиты) — балансировочная ручка «глупости».
- Реальный self-play против `CombatPipeline` для обучения вместо
  синтетических сценариев.

## 6. Боссы: куда движемся

Боссы в перспективе **не «много финтов в руке»**. Боссы — **ограниченный
набор сильных abilities**, которые радикально меняют размен:
дистанционный stun на всю команду, контр-стойка на круг, AoE-добивание.

Финты остаются «языком обычного размена», единым для всех боевых
актёров. ИИ под боссов — это **второй слой над тем же мозгом**: тот же
`MonsterCombatBrain` + расширенный action space (`instant` ветка) +
своя политика с акцентами на ability-теги.

Сейчас босс-поведение использует ту же default-политику, что и миньон.
До отдельной политики дойдём, когда:

1. Каталог монстерских abilities дозреет (минимум 3–5 рабочих
   способностей, не stub).
2. Маршрутизация в `PolicyStore` под `MonsterAIProfileDTO.behavior`
   получит реализацию.

## 7. Что монстр видит и не видит

Видит:

- Свои HP, стамину, токены, руку финтов.
- HP, броню, evasion, parry, block, физическую резистентность каждой цели.
- Активные эффекты на целях (есть ли уже bleed, контроль).
- Сколько живых врагов всего (для тегов вроде `multi_target`).

Не видит и не должен:

- Полный список финтов в руке игрока (только то, что становится известно
  из публичных событий боя — а ИИ это не использует).
- Намерения игрока в этом раунде (он одновременный).
- Бэкенд-метаданные (id-шники реалов, токены сессии, и т.п.) — мозг
  работает только через snapshot-контракт.

Информационная симметрия с игроком — основной принцип.
