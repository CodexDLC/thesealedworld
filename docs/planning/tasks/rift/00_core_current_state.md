# 00. Core Current State

Status: implemented as a dev prototype.

## Goal

Lock the backend behavior that already exists so later work does not drift back into unclear rift ideas.

## Already Implemented

- JSON resources for rift setting, node pool, scale presets and zone assembly presets.
- Random dev rebuild of a rift runtime.
- Separate canvas size and active node count.
- Current presets:
  - `5x5` canvas with `15` active described nodes.
  - `6x6` canvas with `20` active described nodes.
  - `7x7` canvas with `25` active described nodes.
- Void coordinates do not consume node pool descriptions.
- Passage graph is stored in `passage_edges`, not inferred only from grid adjacency.
- Open passages and temporary blocker passages are distinct.
- `debug_map` returns full canvas cells and debug passage edges.
- `map_view` returns player-facing local map data around the current node.
- Movement buttons are generated by backend from validated passage state.
- Void surfaces use setting-level boundary descriptors.
- Temporary blockers return an interactive `inspect_blocker` action with blocker metadata.
- Travel preview contract exists:
  - unknown node: `6000 ms`, transition checks every `2000 ms`, possible events `none/combat`;
  - visited node return: `2000 ms`, no transition events.
- Node entry event preview contract exists separately from transition events.

## Not Yet Implemented

- Real travel/tick runtime.
- Real combat launch from transition interception.
- Node entry event resolver.
- Real temporary blocker resolution through production character skills/attributes/items.
- Stable class/service split for generator logic.
- Database persistence models.
- Final zone instance/meta layer.
- LLM generation of node pools and boundary descriptors.

## Exit Criteria

This task is considered done while current backend rift tests pass and the prototype contracts remain documented by tests.
