# Rift Generation And Balance Tasks

This file tracks generation, monster placement, and encounter-budget planning.

## Template Generation

Rift template inputs:

- Tier.
- Size.
- Setting.
- Ruleset.
- Dominant threat.
- Inhabitants profile.
- Resource profile.
- Quest/contract constraints.

Generated outputs:

- Graph shape.
- Node tags.
- Node descriptions.
- Possible event pools.
- Monster family selection.
- Core placement rules.

Needs owner decision:

- Whether first templates are handwritten JSON, generated by server rules, generated by LLM, or hybrid.
- How many settings ship in MVP.

## Template Reuse

Stored templates can be reused when they match contract parameters.

Minimum variation for reused templates:

- Monster placement changes.
- Resource/reward placement changes.

Optional variation:

- Active events.
- Boss variant.
- Starting path.
- Locked/open branches.
- Visual mood.

Needs owner decision:

- How much variation is required before players stop feeling repetition.

## Encounter Budget From Gear Score

Rift encounters are assembled from the gear score of whoever enters the content: solo character, party, or raid.

Rule direction:

- Solo encounter budget starts from the character's gear score.
- Party encounter budget starts from summed party gear score.
- Raid encounter budget starts from summed raid gear score.
- The encounter builder divides that score by a balance value/curve to get a monster budget.
- The budget is spent on monster count, monster rank, elite packs, support units, or boss pressure.

Draft model:

```text
base_budget = total_gs / divisor
tier_mult = 1.0 + (rift_tier - party_tier) * 0.25
danger_mult = node_danger_weight
final_budget = base_budget * tier_mult * danger_mult
```

Suggested node danger weights:

- Empty or light point: `0.2-0.4`
- Standard combat: `0.8-1.1`
- Dangerous combat: `1.2-1.5`
- Elite point: `1.8-2.5`
- Boss: separate formula

Minimum builder rules:

- Rift tier limits maximum monster tier.
- Setting and tags restrict monster families.
- Node type restricts encounter roles.
- Budget should not always be spent completely.
- Some nodes should be underbudget to create pacing and easy rooms.
- Elites and bosses have per-node limits.
- Large groups should not receive only a swarm of weak monsters; part of the budget upgrades rank, elite pressure, support roles, or boss mechanics.

Needs owner decision:

- Initial `divisor`.
- Whether `party_tier` is symbiote tier, gear tier, average item tier, or a derived readiness tier.
- How much overbudget is allowed.
- Whether easy nodes can be empty in combat-required rifts.
